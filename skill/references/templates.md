# 输出版式模板

> SKILL.md 要求所有输出严格照此执行。目的是保持**一致的可截图观感**——用户截一张图发出去，就是最好的传播。

---

## 1. 积分账本（W1）

```
──────────────────────────────
  麦享掌柜 · 积分账本
──────────────────────────────
  可用积分            {availablePoint} 分
  ── 来龙去脉 ──────────────
  累计获得            {accumulativePoint} 分
  已使用              {usedPoint} 分
  已过期              {expiredPoint} 分
  冻结中              {frozenPoint} 分
  ── 到期提醒 ──────────────
  本月将过期          {currentMouthExpirePoint} 分
  下月将过期          {nextMouthExpirePoint} 分
  上月已过期          {lastMouthExpirePoint} 分
──────────────────────────────
  掌柜批注
  {一段人话解读}
──────────────────────────────
```

**规则**：
- 到期提醒三行只要有一个 > 0，就**置顶**并加 ⚠️。
- 积分为 0 → 走「开张前夜」话术（见第 5 节），不输出空账本的尴尬感。
- 绝不出现「建议您先消费」「不如点个套餐攒分」等引导消费表述。

## 2. 兑换榜单（W2）

```
──────────────────────────────
  积分商城 · 真实可兑榜单
  {total_raw} 件在售 → 去伪后 {N} 件真可兑
──────────────────────────────
  {rarity_icon} {rarity_level}
  {商品名}          {point} 分   {unit_price} 分/元
  {商品名}          {point} 分   {unit_price} 分/元
  └ {drop_flag} {days_left} 天后下架 · 你还差 {gap} 分

  ── 已剔除 {M} 件 ──────────────
  名存实亡 {X} 件（标 status=2 上架，实则已过期）
    ☠️ {商品名}   {point} 分
       {下架时间}
  现金商品 {Y} 件（point=0，派对/品鉴会/体验营）
──────────────────────────────
  图鉴进度   {已兑换} / {N}
  已绝版收藏 {X} 件（见图鉴 · 绝版栏）
  限时掉落   {当前无 / N 件}
──────────────────────────────
```

**规则**：
- 榜单按 `unit_price` 升序（越靠前越划算）。
- 无券面价者排在末尾，注明「无券面价参考」。
- 「已剔除」区块**必须展示**——这是去伪能力的证据，也让用户知道没漏东西。

## 3. 图鉴卡片（表达层）

```
  ┌────────────────────────────┐
  │  🔱 传说 · 金拱门限定        │
  │                            │
  │  Nike Book 2 联名款         │
  │  8888 分                   │
  │                            │
  │  ☠️ 已绝版                  │
  │  兑换窗 2026-06-05 两小时    │
  └────────────────────────────┘
```

**稀有度**（见规划 11.1）：≥5000 🔱传说 / ≥2000 💎史诗 / ≥500 🔷稀有 / 其余 ⚪普通。
**叠加**：≤7 天 ⚠️，≤3 天 🔴。

**文案纪律**：绝版栏只陈述事实，**禁用「可惜」「你错过了」「错过等一年」**等制造焦虑的措辞。

## 4. 抽奖参谋（W3）

```
  麦麦积分抽奖（{activityStatusText} · 至 {endTime}）
  单次 {drawPoint} 分 · 奖池 {N} 品

  奖池结构
    {按 typeText 分组列出}

  掌柜算给你看
  {期望值解读：花 X 分，最差回 Y 分，但概率是 1/N；
   折扣券折合 A~B 分/元，与直接兑换对比}

  结论：{积分紧张 → 换确定项；富余 → 可抽着玩}

  ⚠️ 抽奖不可逆，抽一次扣 {drawPoint} 分。
  说「抽」我才动手。
```

**铁律**：资格只报 `drawDecision.resourceEligible` 的结果，不自行推断。

## 5. 攒分路径（积分为 0 时）

  要不要看看这 {N} 件能换什么？
```

## 6. 下单确认摘要（安全红线）

```
  ── 兑换确认 ─────────────────
  商品：{spuName} / {skuName}
  消耗：{point} 积分
  当前可用：{availablePoint} 分（兑换后剩 {rest} 分）
