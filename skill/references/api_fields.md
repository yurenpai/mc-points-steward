```python

# ✅ 必须照抄官方拼写
item.get("currentMouthExpirePoint")
```

## 2. `mall-points-products` —— 商城列表（已实测 14:55，**16:07 用 catRuleIds 复测并更正**）

返回 `data` 数组，每个元素 11 个字段：

| 字段 | 含义 | 备注 |
|---|---|---|
| `spuId` | 商品 ID（整数） | 详情页与下单都要用 |
| `spuName` | 商品名 | **券面价藏在这里**（到店支付价，不是市价），如"6.9元可乐麦炫酷" |
| `point` | 所需积分（字符串） | `"0"` 表示现金商品 |
| `price` | 所需金额（字符串） | **积分商品恒为 `"0"`** |

| `catName` | 类目 | 到店专用 / 玩具 / 鞋袜 / 品鉴会 / 派对类 |
| `spuImage` | 图片 URL | |
| `selling` | 卖点文案 | |
| `shopId` | 门店 ID | |

### ⚠️ 入参 `catRuleIds`（2026-10-12 16:07 补测：默认查询会漏商品）

支持类目筛选，**逗号分隔可多选**：

| 值 | 类目 |
|---|---|
| `1>4` | 商品券（非预付优惠券）—— 真可兑商品几乎全在这里 |
| `2` | 实物商品 |
| `2>8` | 周边产品 |
| `2>9` | 实物礼品卡 |
| `1>6>20` / `1>6>21` / `1>6>22` / `1>6>25` / `1>6>34` | 生日派对 / 主题派对 / 麦麦体验营 / 品鉴会 / 读书会 |
| `1>6>40` | 积分兑换活动 |

**不传 `catRuleIds` 的默认查询返回不完整：**

| 查询方式 | 件数 | 其中真可兑 |
|---|---:|---:|
| 默认（不传参） | 50 | **7** ❌ |
| `1>4` | 24 | 9 |
| `2>8` | 3 | 0 |
| **逐类目合并去重（正确）** | **27** | **9** ✅ |

默认查询漏掉 3 件：`17075`（3.9元圆筒冰淇淋 100 分）、`17078`（16.9元2份麦辣鸡翅 200 分）、
`17643`（酸黄瓜吧唧礼盒 800 分）。**前两件都是真能兑的** → 漏报率 2/9 ≈ 22%。

> **结论：必须逐类目查询后按 `spuId` 合并，不能只调一次默认查询。**
> 已固化为 SKILL.md 数据陷阱第 8 条 + `tests/test_cat_merge.py` 25 条断言。

## 4. `mall-product-detail` —— 商品详情（✅ 2026-10-12 18:34 实测，**真可兑 9 件全量**）

入参 `spuId`（整数，必填）。对 17073~17081 逐一调用，无抽样。

### 字段

| 字段 | 说明 | 实测值 |
|---|---|---|
| `spuId` / `spuName` / `shopId` | 商品 ID / 名 / 店铺 | `shopId` 恒为 **2**（`mall-create-order` 仅支持 2） |
| **`skuList[]`** | **SKU 规格列表** | 实测 9 件**均为单 SKU** |
| └ `skuId` | 下单必传 | 17779~17787（与 spuId 一一对应，非同一数字） |
| └ `points` | 该 SKU 所需积分 | 与列表接口 `point` 一致 |
| └ `price` | 所需金额 | **恒为 `"0"`** |
| └ **`extTradePrice`** | **券核销额外支付金额** 🔴 | **列表接口没有这个字段** |
| └ `specList[]` | 规格（specMain/specItem） | 实测**全为空**，无规格可选 |
| **`upDate` / `downDate`** | 上架 / 下架时间 | ⚠️ **不叫 upTime/downTime**——与列表接口不同名 |
| `categoryRuleId` | 类目规则路径 | `"1>4>13"`（三级，比查询用的 `1>4` 多一级） |
| `spuCategory` | 1 虚拟 / 2 实物 | 实测 9 件全为 `"1"`（虚拟券） |
| `spuLimit` | 限购：`ruleType` / `cycle` / `limitCount` / `baseCount` / `limitSingle` | 实测 `limitCount=-1`（不限购）、`baseCount=1` |
| `note` | 购买须知，**HTML 长文本**（约 1.5 KB） | ⚠️ 官方要求原文展示，**禁止解析取数** |
| `detail` | 详情图（HTML `<img>`） | 纯展示 |
| `images[]` | 商品图 URL 数组 | |
| `partyPeople` / `partyAge` / `partyRange` / `partyType` | 派对相关 | 商品券场景**全为空/0** |

### 🔴 实测结论：真可兑 9 件，全部需到店另付现金

| spuId | 商品 | 积分 | `extTradePrice` | 商品名内的数字 |
|---:|---|---:|---:|---:|
| 17073 | 6.9元可乐麦炫酷 | 50 | **6.9** | 6.9 ✅ |
| 17074 | 6.9元香芋派/菠萝派任选 | 50 | **6.9** | 6.9 ✅ |
| 17075 | 3.9元圆筒冰淇淋 | 100 | **3.9** | 3.9 ✅ |
| 17076 | 10.9元指定小食任选 | 100 | **10.9** | 10.9 ✅ |
| 17077 | 10.9元指定小食任选 | 200 | **10.9** | 10.9 ✅ |
| 17078 | 16.9元2份麦辣鸡翅 | 200 | **16.9** | 16.9 ✅ |
| 17079 | 16.9元麦辣可乐组合 | 500 | **16.9** | 16.9 ✅ |
| 17080 | 17.9元板烧可乐组合 | 500 | **17.9** | 17.9 ✅ |
| 17081 | 21.9元巨无霸可乐组合 | 800 | **21.9** | 21.9 ✅ |

> **纯积分白拿：0 / 9。** `extTradePrice` 与商品名里的数字 **9/9 完全恒等**——
> 所以商品名里的数字是**券后支付价**，不是市价（见 SKILL.md 陷阱第 2、9 条）。
> 现金区间 **¥3.9 ~ ¥21.9**。已由 `tests/test_hidden_cost.py`（42 断言）钉死。

### 顺带澄清的「同名陷阱」

「10.9元指定小食任选」两个 spuId 的 `note` 内容不同：

| spuId | 积分 | 到店另付 | 实际兑换内容（取自 `note`） |
|---:|---:|---:|---|
| **17076** | 100 | 10.9 | 中薯条 / 奥利奥麦旋风 任选 1 件 |
| **17077** | 200 | 10.9 | 麦乐鸡-4块 / 麦辣鸡翅-2块 / 那么大鸡排（椒盐风味）任选 1 件 |

→ **不是"同物不同价"，而是"同名不同物"**。旧的"推荐最低分那个"是错的，
正确做法是展示内容差异让用户按想吃什么选。

## 5. `mall-create-order` —— 兑换下单（⚠️ 契约已确认，**未实调**）

**为什么不实调**：一旦调用即产生**真实订单**（涉及真实券码与积分扣减），本项目不代为发起真实交易。
参赛演示一律走到"待确认"这一步停住，不真实下单。

### 入参（来自 schema）

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `skuId` | integer | ✅ | 从 `mall-product-detail` 的 `skuList[].skuId` 取（**不是 spuId**） |
| `spuCategory` | string | ✅ | `"1"` 虚拟商品 / `"2"` 实体物品，从详情取 |
| `addressId` | string | 条件 | **仅 `spuCategory="2"` 时必填**（实物要配送地址） |
| `count` | integer | 否 | 兑换数量，默认 1 |

### 硬约束（schema 原文）

- **仅支持 `shopId=2`**（实测所有积分商品的 `shopId` 均为 2，符合）
- 兑换多个商品必须**分别下单且排队**：等前一个订单响应成功后再调下一个
- **禁止**跳过调用直接生成"下单成功"结论；**禁止**复用已有订单冒充
- 不适用派对/品鉴会/体验营等需选门店场次的场景 → 那些走 `party-order-create`
- 官方要求：所有校验（限购、库存、价格）**以下单接口返回为准**，不得用详情里的 `spuLimit` / `note` 做前置校验

### 返回

`orderId` / `coupons[]` / `couponId` / `orderItemId` / `couponCodes[]` / `receiveQuantity` /
`orderItemStatus`（1 成功 / 0 失败）/ `orderStatus` / `status`（1 全部成功 / 2 部分成功 / 0 失败）

## 6. `query-my-prizes` —— 我的奖品（✅ 结构已确认，数据为空）

返回 `data` 对象：`status{code,message}` / `prizes[]` / `pageNum` / `pageSize` / `hasMore` / `nextCursor` / `truncated`。

实测（账号无中奖记录）：`status.code = "SUCCESS"`、`prizes = []`、`hasMore = false`、`truncated = false`。

→ **"空"与"失败"要区分**：`status.code=SUCCESS` 而 `prizes` 为空 = 确认没有，不是没查到。
→ `prizes[]` 元素字段：`id` / `name` / `imageUrl` / `prizeType` / `recordTime` / `status` /
   `statusText` / `timeRemindText`，按 `recordTime` 倒序。
→ 入参 `pageSize` 最大 **50**，超出会归一化。

## 7. `mall-order-list` —— 商城订单（✅ 结构已确认，数据为空）

返回 `data` 是**数组包对象**（不是直接对象）:`[{hasNext, lastId, list[]}]`。

实测：`[{hasNext:false, lastId:0, list:[]}]`。
`list[]` 元素字段：`orderId` / `orderStatus` / `orderStatusTitle` / `totalCount` / `goods[]`。
入参 `size` 默认 10，**超过 10 按 10 条**。

## 8. `campaign-calendar` —— 活动日历（✅ 2026-10-12 18:33 实测）

入参 `specifiedDate`（可选，`yyyy-MM-dd`）：传入则只返回**锚点当天 + 前后各一个最近有活动的日子**（共 3 天）；
**不传则返回当前月全部活动**。

返回的是 **Markdown 文本 + 图片 URL**（非结构化 JSON），按日期分组，每天若干活动，
每个活动含：标题 / 内容介绍 / 图片（`<img src=...>`）。

实测 10 月共 **14 个活动日**，其中：

- **麦当劳 × PEACEMINUSONE（G-DRAGON）联名三弹**：棒球帽 10-08 开售、徽章 10-15、丝巾 10-22，
  每弹都有「**APP 专享积分抢先购 10:40**」——这是唯一把积分和限定周边连起来的点
- **学生专属 49 元 / 150 天麦金学期卡**（0.33 元/天）
- 韩式风味系列新品、蓝莓爆爆珠麦旋风、灰焰圆筒、麦咖啡浓浓黑巧等新品
- 过家家派对 / 趣读派对 / 麦麦派对（亲子向）

⚠️ 注意：返回里的日期是"活动展示日"，**不等于开售日**（如棒球帽 10-08 开售，但 10-13 仍在列表里）。
引用开售时间必须读正文文案，不能把分组日期当开售日。

## 5. 降级场景表

| 场景 | 降级策略 |
|---|---|
| mcd-mcp 未接入/未授权 | 提示先完成接入，附配置要点（Authorization 必须带 **Bearer** 前缀），绝不伪造数据 |
| 商品列表返回空 | "商城当前无可兑商品"，不输出空榜 |
| 缺 `downTime` | 归"时效未知"栏，不标临期 |
| 积分商品缺券面价 | 单列"无券面价参考"，不填 0、不排名 |
| `drawDecision` 缺失 | 不推断资格，原样展示 + "以 App 页面为准" |
| 下单/抽奖失败 | 原样转述错误，不重试、不猜测原因 |
| 积分不足 | 展示攒分路径，严禁引导消费 |

统一话术前缀：**「掌柜没法确认这件事」**——区分"没查到"与"确认没有"。
